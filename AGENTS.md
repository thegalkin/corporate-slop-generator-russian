# AGENTS.md

Инструкции для ИИ-агентов, работающих с этим репозиторием.
Человеческая версия тех же инструкций — в разделе «Сборка: инструкция для
агентов» файла README.md.

## Что это

Генератор корпоративной тарабарщины на русском языке. Go, без зависимостей
в рантайме. Морфология (падеж, число, род, вид глагола) считается по
таблицам, собранным из OpenCorpora на этапе сборки.

## Команды

```bash
make build      # go build -o bin/cbsg ./cmd/cbsg
make test       # go test ./...
make check      # независимая проверка грамматики (нужен Python: make venv)
make lexicon    # пересобрать таблицы форм из OpenCorpora
make run        # пять предложений
```

`make check` и `make lexicon` требуют `.venv` (создаётся через `make venv`,
ставит `pymorphy3` и `pyyaml`). **В рантайме Python не нужен**: бинарник
собирается и работает без него.

## Структура

| путь | что это |
|---|---|
| `cmd/cbsg` | командная строка: `-n`, `-seed`, `-mode`, `-quiet`, `-version` |
| `internal/lexicon` | типы данных + `data/lexicon.json` (генерируется) |
| `internal/morph` | лемма → форма; согласование прилагательного |
| `internal/grammar` | рамки предложений и слоты (`frames.go`, `grammar.go`) |
| `internal/generator` | сборка предложений, абзацев, отчётов |
| `tools/lexicon.yaml` | **источник словаря**, единственный редактируемый |
| `tools/build_lexicon.py` | сборка `data/lexicon.json` + проверки |
| `tools/check_grammar.py` | проверка грамматики готового текста |
| `demo/` | примеры вывода |

## Правила

1. **`internal/lexicon/data/lexicon.json` не редактируется руками.** Он
   генерируется из `tools/lexicon.yaml` командой `make lexicon`. Правь
   источник, потом пересобирай.

2. **Рантайм остаётся чистым.** Никаких зависимостей, никакого Python в
   рантайме. `pymorphy3` — только для сборки словаря и для проверки.

3. **Порядок заполнения слотов значим.** В `morph.RenderParts` сначала
   собираются существительные, потом прилагательные: прилагательное
   согласуется с *ближайшим следующим* существительным, и ему нужно знать его
   род и падеж. Не меняй этот порядок.

4. **Состояние слотов сбрасывается.** Рамки живут в общей таблице
   (`grammar.Frames`), поэтому `Prepare` обязан обнулять изменяемые поля
   (`Subj.text`, `Subj.info`, `SubjAdj.adj`). Иначе состояние «залипнет» от
   предыдущего предложения — такой баг уже был.

5. **Падеж задаёт рамка, не слова.** Не пиши падеж вручную в тексте рамки:
   используй слоты `noun(Case)`, `attr(Case)`, `PrepSlot{Prep: "о"}`.
   Предлог «о» сливается сам: `mergePrep` превращает «о идее» в «об идее».

6. **Падеж дополнения — свойство глагола.** В `tools/lexicon.yaml` есть
   секция `genitive_verbs`: глаголы, требующие родительного падежа
   («достигать цели»). Слот `vp` берёт падеж из валентности глагола.

## Как добавить слово

1. Дописать в нужную секцию `tools/lexicon.yaml`. Ключ — русское слово,
   значение — английский оригинал. Пробелы в ключе — через подчёркивание.

   ```yaml
   nouns:
     синергия: synergy
   ```

   Составные существительные — в секцию `phrases`:

   ```yaml
   phrases:
     модель_бизнеса:
       en: business model
       parts:
         - {kind: noun, lemma: модель}
         - {kind: noun, lemma: бизнес, case: gen}
   ```

   Слова, которых нет в OpenCorpora, — в секцию `loans` (парадигма руками)
   либо с шаблоном:

   ```yaml
   loans:
     ширший:
       kind: adjective
       template: хороший
       from: хорош
       to: ширш
   ```

2. `make lexicon` — сборщик проверит всё, что можно проверить, и упадёт с
   точным списком проблем, если что-то не так.

3. `make check` — убедиться, что вывод по-прежнему грамматичен.

4. `go test ./...` — инварианты текста (нет двойных пробелов, нет пробела
   перед знаком, есть точка в конце).

## Как проверить свои изменения

```bash
make build && make test && make check
```

`make check` генерирует 5000 предложений и разбирает их анализатором
pymorphy3, проверяя согласование прилагательных с существительными и
глаголов с подлежащими. Ноль нарушений — ожидаемая норма. Если появились
нарушения, смотри примеры в выводе валидатора.

Слова, которых нет в OpenCorpora, попадают в отдельный отчёт
«ожидаемые займы» — это не ошибка, но их формы стоит проверить глазами.

## Чего делать нельзя

* Хранить секреты, токены, ключи в коде или в `tools/lexicon.yaml`.
* Класть абсолютные пути (`/home/...`, `/Users/...`) в код, скрипты и
  документацию: в репозитории должны быть только относительные пути.
* Добавлять в рантайм зависимость от Python или от внешних пакетов.
* Коммитить `.venv/`, `bin/`, `__pycache__/`.
